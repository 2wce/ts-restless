## Installation

ts-restless v4 supports Next.js **15 and 16**, the current Maintenance and Active LTS lines in the [Next.js support policy](https://nextjs.org/support-policy) (checked 2026-11-06). Next.js 12–14 are unsupported. Upgrade an older application using the [official Next.js upgrade guides](https://nextjs.org/docs/app/guides/upgrading) before migrating to v4, and use a current patched release.

This package serves **Pages Router API routes** on supported Next majors. For App Router or Pages Router Edge handlers, use [`@ts-restless/serverless/next`](/server/serverless/next-serverless). The maintained [Next 16 example](https://github.com/2wce/ts-restless/tree/main/apps/example-next) demonstrates both integrations.

## Usage

For maximum type safety, by default `@ts-restless/next` uses a single endpoint for all routes.

<Callout type="info" title="Multiple Endpoints">
  It is possible to split out to multiple endpoints by having multiple
  [...ts-rest].tsx files in different folders, so long as the routers you use
  all begin with the same path e.g. all `/posts` endpoints in a posts folder.
</Callout>

```typescript
// pages/api/[...ts-rest].tsx
import { createNextRoute, createNextRouter } from '@ts-restless/next';

// `contract` is the AppRouter returned by `c.router`
const postsRouter = createNextRoute(contract.posts, {
  createPost: async (args) => {
    const newPost = await posts.createPost(args.body);

    return {
      status: 201,
      body: newPost,
    };
  },
});

const router = createNextRoute(contract, {
  posts: postsRouter,
});

// Actually initiate the collective endpoints
export default createNextRouter(contract, router);
```

`createNextRouter` is a function that takes a contract and a complete router, and creates endpoints, with the correct methods, paths and callbacks.

It's also possible to create a handler for a single contract route.

```typescript
// pages/api/posts/index.tsx
import { createSingleRouteHandler } from '@ts-restless/next';

export default createSingleRouteHandler(api.posts.createPost, async (args) => {
  const newPost = await posts.createPost(args.body);

  return {
    status: 201,
    body: newPost,
  };
});
```

`createSingleRouteHandler` is a function that takes a single contract route and a handler, and creates a `nextApiHandler`

### Multipart request bodies

The adapter validates the `req.body` produced by Next.js. Next's built-in API body parser decodes JSON and `application/x-www-form-urlencoded` bodies, but passes `multipart/form-data` through as text, so a multipart object schema fails validation. Your application owns multipart parsing, field decoding and file handling, as Multer does for Express and Nest.

Serve multipart routes from their own API route file, disable Next's body parser there, parse the body and assign the result to `req.body` before calling the ts-restless handler. The native `Response.formData()` parser is enough for small uploads:

```typescript
// pages/api/posts/[id]/image.ts
import type { IncomingMessage } from 'node:http';
import type { NextApiRequest, NextApiResponse } from 'next';
import { createSingleRouteHandler } from '@ts-restless/next';

// Disabling the parser also removes Next's default 1 MB request limit.
export const config = { api: { bodyParser: false } };

const maxUploadBytes = 4 * 1024 * 1024;

const uploadImage = createSingleRouteHandler(
  contract.uploadImage,
  async ({ params, body, req }) => {
    // Server body types omit File fields; read the validated parsed value.
    const image: File = req.body.image;
    const url = await storeImage(params.id, body.title, image);
    return { status: 201, body: { url } };
  },
);

async function readFormData(req: IncomingMessage) {
  const chunks: Buffer[] = [];
  let size = 0;
  for await (const chunk of req) {
    size += chunk.length;
    if (size > maxUploadBytes) return null;
    chunks.push(chunk);
  }
  return new Response(Buffer.concat(chunks), {
    headers: { 'content-type': req.headers['content-type'] ?? '' },
  }).formData();
}

export default async function handler(req: NextApiRequest, res: NextApiResponse) {
  if (req.headers['content-type']?.startsWith('multipart/form-data')) {
    const form = await readFormData(req);
    if (!form) {
      res.status(413).json({ message: 'Upload too large' });
      return;
    }
    req.body = {
      title: form.get('title') ?? undefined,
      tags: form.getAll('tags'),
      width: form.get('width') ?? undefined,
      image: form.get('image') ?? undefined,
    };
  }
  return uploadImage(req, res);
}
```

The contract is the same as in the [App Router example](/server/serverless/next-serverless#multipart-and-form-bodies). Match field decoding to the route's [multipart field encoding](/client/fetch#form-data-multipartform-data): with the default `form` encoding, use `getAll()` for repeated array fields and coerce or `JSON.parse` numbers, booleans, `null` and nested objects; with `legacy-json`, `JSON.parse` every ordinary field. Server-side body types omit `File` fields on multipart routes, so declare required files in the schema for validation and read them from `req.body`. `Response.formData()` buffers the whole body; use a streaming parser such as Busboy or Formidable for large uploads, assigning its fields and files to `req.body` the same way.

Keep JSON routes in the catch-all `createNextRouter` file, where Next's body parser stays enabled.

### JSON Query Parameters

To handle JSON query parameters, you can use the `jsonQuery` option.

```typescript
export default createNextRouter(contract, router, { jsonQuery: true });
```

### Response Validation

To enable response parsing and validation, you can use the `responseValidation` option.
If there is a corresponding response Standard Schema defined in the contract for the returned status code, the response will be parsed and validated.
If validation fails a `TsRestResponseValidationError` will be thrown causing a 500 response to be returned.

```typescript
export default createNextRouter(contract, router, { responseValidation: true });
```

### Error Handling

You can create a global error handler to handle any thrown errors by using the `errorHandler` option.
This includes response validation errors.

```typescript
import { TsRestResponseValidationError } from '@ts-restless/core';

export default createNextRouter(contract, router, {
  responseValidation: true,
  errorHandler: (error: unknown, req: NextApiRequest, res: NextApiResponse) => {
    if (error instanceof TsRestResponseValidationError) {
      console.log(error.cause);
      res.status(500).json({ message: 'Internal Server Error' });
      return;
    }
  },
});
```

#### Request Validation Error Handling

The default behavior when validating request schema is to return a 400 status with the corresponding validation error.
To customize handling of the request validation errors enable the `throwRequestValidation` option.
This option allows you to handle the request validation error in the global `errorHandler` function.

```typescript
export default createNextRouter(contract, router, {
  throwRequestValidation: true,
  errorHandler: (error: unknown, req: NextApiRequest, res: NextApiResponse) => {
    if (error instanceof RequestValidationError) {
      if (error.body !== null) {
        res
          .status(400)
          .json({ message: 'Malformed Body', errors: error.body.issues });
        return;
      }

      res.status(400).json({ message: 'Bad Request' });
      return;
    }
  },
});
```

```typescript
export class RequestValidationError extends Error {
  constructor(
    public pathParams: StandardSchemaError | null,
    public headers: StandardSchemaError | null,
    public query: StandardSchemaError | null,
    public body: StandardSchemaError | null,
  ) {
    super('[ts-rest] request validation failed');
  }
}
```
