The report's request/response labels are inconsistent with its stack traces; the table names the observed boundary instead. Shared core response evaluation and other server adapters are unchanged. Undefined JSON has no wire representation; use `c.noBody()` for interoperable empty responses rather than expecting a JSON decoder to produce undefined.

## Reproduction and verification

- `pnpm exec vp test run --project serverless` before source changes: **10 expected failures, 86 passed**. Failures included the early JSON parser and AWS binary mapper. Log: `/private/tmp/ts-restless-empty-red.log`.
- Same focused command after two source changes: **96 passed across 9 files**; malformed/whitespace JSON and normal JSON remain covered. Log: `/private/tmp/ts-restless-empty-green.log`.
- `pnpm exec vp test run --project core -t delete` against unchanged alpha.4 core: **3 passed**, 278 skipped. Log: `/private/tmp/ts-restless-696-baseline.log`.
- Existing packed-consumer suite extended with Standard Schema undefined contracts and real Fetch/AWS v1/v2 ESM/CommonJS execution; strict declaration checks remain enabled across four validator profiles and both Next baselines. Initial broad checks caught test-fixture typing mistakes (body omitted from undefined-input request types; AWS results can include strings), corrected without weakening checks. Broad final gates are recorded in the [implementation plan](../plans/2026-11-10-serverless-empty-body.md).

These are local source/native and installed-artifact checks, not a deployed Lambda or reconstruction of every historical application. Changes require a release after alpha.4; neither this evidence nor a draft PR proves publication. See [consumer migration](../../apps/docs/content/docs/server/serverless/fetch-runtimes.md#empty-request-and-response-bodies).

Review correction on 2026-11-10: a BOM-only body has three wire bytes but decodes to an empty string. A new regression failed under the initial text-length check. The final decoder checks ArrayBuffer byte length before UTF-8 decoding, preserving BOM-only parse errors and BOM-prefixed valid JSON. The focused suite now includes these cases; final verification is recorded in the plan.
