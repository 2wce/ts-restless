# OpenAPI conversion implementation plan

**Goal:** Resolve [#4](https://github.com/2wce/ts-restless/issues/4), [#39](https://github.com/2wce/ts-restless/issues/39), [#40](https://github.com/2wce/ts-restless/issues/40) and [#41](https://github.com/2wce/ts-restless/issues/41) on a branch from current main.

**Design:** Retain the schema transformer boundary, requiring an explicit converter at the validator-independent entry. Keep the historical generator and converter in an opt-in `/legacy` entry. Support OpenAPI 3.0.2 and 3.1.0 with explicit dialect selection and matching model types. Converters may return `{ schema, required }` to describe whole-value presence without running validation. Plain schema returns describe required values. Standard Schema is a validation interface and cannot supply JSON Schema or presence information.

Zod3 cannot distinguish constant from callback defaults without evaluating them. Its compatibility converter omits inferred defaults and accepts explicit constant defaults in OpenAPI metadata. It inspects optional/default wrappers without parsing values. Root query/header/path compositions are rejected with a diagnostic instead of silently dropping fields. Nested compositions remain representable.

**Constraints:** Node 26.12.0; pnpm 12.14.0; strict installed consumers; native adapter boundaries; no merge, version command or publication. Changes to the default converter, OpenAPI types and default annotations are documented as part of the unreleased v4 migration.
